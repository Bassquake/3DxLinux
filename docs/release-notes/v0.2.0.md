## 3DxLinux 0.2.0 — Calibrate and per-application profiles

This release adds the two remaining 3DxWare settings that 0.1.0 lacked:
**Calibrate** and **per-application settings**. Both were tested on a real
SpacePilot Pro (firmware 4.11); see `docs/HARDWARE_TESTS.md`.

### New

**Calibrate (re-zero).** This sends the same firmware command as 3DxWare's
*Calibrate* button and its "Rezero device" action: HID feature report `0x07`,
recovered from `UdDevRezero` in `HIDDev.dll`. As on Windows, devices with
firmware older than 2.00 are skipped. Three ways to trigger it:

- run `tdxctl calibrate` with the cap untouched;
- set `calibrate_button = V3DK_…` to bind it to a button;
- set `calibrate_on_start = yes` to run it whenever a device connects.

**Per-application profiles.** Each `/etc/tdxd.d/<name>.conf` file is layered on
top of `/etc/tdxd.conf` while a matching application has focus.

- **Matching:** `match = blender, blender-*` (case-insensitive, `*` and `?`
  allowed). Without it, the file name is used.
- **Contents:** any setting except the daemon-wide ones (sockets, uinput,
  spnav, LCD on/off).
- **Example:** `blender.conf.example` is installed to `/etc/tdxd.d/`.
- **Focused application:**
  - **`tdx-focus`:** a new helper for X11 or sway. Enable it with
    `systemctl --user enable --now tdx-focus`.
  - **Fallback:** without it, 3DxLinux uses the newest program connected to the
    spacenavd socket (e.g. Blender). This also works on Wayland desktops.

**`tdxctl`.** A new command-line tool for the running daemon, with the
commands `status`, `profiles`, `focus`, `calibrate` and `reload`. `status`
shows the active profile, the focused application and each device's firmware
version.

### Changed

- `invert_tx … invert_rz` are now settings instead of toggles, so a profile can
  turn one off again. Existing configs behave the same.
- Repeating a `key_…` or `led_color_…` entry now replaces the earlier one
  instead of adding to it. `key_<id> = none` removes a binding.
- The README has a table mapping each 3DxWare setting to its 3DxLinux equivalent.

### Fixed

- A crash at startup with a real device ("buffer overflow detected") in the
  firmware-version lookup, found during hardware testing before release.

### Downloads

| File | For |
|---|---|
| `tdxd-0.2.0-linux-x86_64.tar.gz` | 64-bit Intel/AMD PCs |
| `tdxd-0.2.0-linux-arm64.tar.gz` | 64-bit ARM (Raspberry Pi 4/5 with a 64-bit OS, etc.) |
| `tdxd-0.2.0-SHA256SUMS` | checksums for both archives |

The binaries are statically linked: `tdxd`, `tdx-lcd` and `tdxctl`, plus the
`tdx-focus` script.

### Install or upgrade

```bash
tar xzf tdxd-0.2.0-linux-x86_64.tar.gz && cd tdxd-0.2.0-linux-x86_64
sudo ./install.sh
sudo systemctl restart tdxd   # if it was already running
```

An existing `/etc/tdxd.conf` is kept. To see the new options, compare it with
the `tdxd.conf` in the archive (`control_socket`, `profile_dir`,
`calibrate_button`, `calibrate_on_start`).
