## 3DxLinux 0.3.4 — KDE Plasma and FreeCAD

This release makes the SpacePilot Pro work properly on a KDE Plasma desktop and
in FreeCAD:

- the LCD and the per-application profiles follow the app you're using;
- FreeCAD's view keys work;
- the mouse cursor no longer moves with the cap;
- the DOM and PAN ZOOM keys do the right thing.

Everything was tested on Kubuntu 26.04 LTS (Plasma, Wayland) with a SpacePilot
Pro.

### New

**Focus tracking on KDE Plasma.** 3DxLinux now knows which app has the focus on
Plasma, on Wayland as well as X11. Function Keys shows that app's name, and its
per-application profile (`/etc/tdxd.d/<app>.conf`) switches in automatically. A
small KWin script reports each window you switch to. The packages now start
this (`tdx-focus`) for every user; before, nothing started it, so the LCD
always said "default".

**FreeCAD's view keys.** When FreeCAD has the focus, Top, Front, Right, Left,
Bottom, Back, ISO1, Roll +/− and Fit now send FreeCAD's own keyboard shortcuts.
FreeCAD on Linux gets these keys only as numbered buttons and does nothing with
them by default. The new profile is `/etc/tdxd.d/freecad.conf`. FreeCAD's
number shortcuts need a keyboard layout whose top row types digits.

**For profile writers:**

- `key_… = KEY_V, KEY_F` sends a **sequence**: the keys are tapped one after
  another. `KEY_A + KEY_B` is still a chord held with the button.
- `lcd_label_V3DK_TOP = Top View` names any key on the LCD, so a key that sends
  a shortcut can still read "Top View" instead of "2".

### Fixed

- **The mouse cursor moved with the cap.** There were two causes. Linux's
  standard driver also turns the SpacePilot into a mouse, which the desktop
  followed. 3DxLinux's own virtual device also counted as a pointer, because it
  carried keyboard keys too. The udev rule now hides the SpacePilot's own mouse
  device from the desktop. 3DxLinux's keys come from a separate "(tdxd keys)"
  device, so its 3D mouse device is a plain joystick that the desktop ignores.
- **DOM and PAN ZOOM were swapped** on the SpacePilot Pro: the DOM key turned
  pan/zoom on and off and PAN ZOOM the dominant axis. 3DxWare's device table
  lists the two the other way round from what the hardware sends; 3DxLinux now
  corrects that.
- **Upgrading from a workaround.** A copy of 3DxLinux's udev rule in
  `/etc/udev/rules.d` (the workaround for 0.3.1's idle-LCD problem) replaced
  the packaged rule, so later fixes to it never applied. The packages now
  remove such copies of 3DxLinux's own rule.

### Upgrading

- **From a 0.3.x package:** double-click the 0.3.4 one and install it. Then
  restart FreeCAD (and any other 3D app): installing restarts 3DxLinux, and the apps
  don't reconnect to it on their own.
- **From `install.sh`:** run the new `sudo ./install.sh`.

### Hardware status

On Kubuntu 26.04 LTS (KDE Plasma, Wayland) with a SpacePilot Pro, test builds
with these changes were installed:

- the LCD header follows the focused app;
- DOM and PAN ZOOM switch their own settings;
- in FreeCAD the view keys work and the cap navigates;
- the cursor stays still.

Focus tracking on GNOME (Wayland), the `.rpm` and the arm64 packages are
untested.
