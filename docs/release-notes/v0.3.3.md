## tdxd 0.3.3 — Settings take effect immediately

The settings panel now works like 3DxWare on Windows: every change takes effect
as soon as you make it. This release also fixes two problems with upgrading
the packages. All three were tested on Kubuntu 26.04 LTS with a SpacePilot Pro.

### Changed

**Settings apply immediately.** Before, the panel saved `/etc/tdxd.conf` only
when you closed its window, so for example switching the LEDs off did nothing
while it was open. Now each change is saved and tdxd reloads straight away.

- **Password:** `/etc/tdxd.conf` belongs to root, so the system asks for your
  password at the first change and then remembers it for a few minutes.
- **No waiting:** the panel stays responsive while the password dialog is open.
- **If you cancel the password prompt,** the panel stops asking and saves when
  you close the window, as before.

### Fixed

- **After an upgrade the device could stay undetected.** The package only
  restarted tdxd if it was already running, so a stopped tdxd stayed stopped.
  Installing or upgrading now always (re)starts tdxd, and the LCD Manager for
  each logged-in user, unless that user turned it off.
- **Old menu entries stayed after uninstalling.** Importing the 3DxWare look
  puts copies of the "3D Mouse Settings" and "LCD Manager" entries in your home
  folder, for the 3Dconnexion icons, and nothing removes those. The entries and
  those copies now carry `TryExec=`, so the menu hides them once the program is
  gone.

### Upgrading

- **From a 0.3.x package:** double-click the 0.3.3 one and install it.
- **If you imported the 3DxWare look with 0.3.1 or 0.3.2:** those menu copies
  don't have `TryExec` yet. Click **Import 3DxWare look…** in the settings
  panel's About window once more to replace them (or delete
  `~/.local/share/applications/tdx-*.desktop`).
- **From `install.sh`:** run the new `sudo ./install.sh`.

### Hardware status

On Kubuntu 26.04 LTS with a SpacePilot Pro, a test build with these changes
was installed over 0.3.1. tdxd started and found the device, and the LEDs
switched as soon as they were toggled in the settings panel, after one
password prompt. The `.rpm` and arm64 packages are still untested on hardware.
