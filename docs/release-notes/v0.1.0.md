## 3DxLinux 0.1.0 — first test release

`tdxd` is a Linux user-space driver for 3Dconnexion devices, focused on the
**SpacePilot Pro** (046d:c629) and its LCD. It was rebuilt from a
reverse-engineering of the Windows package 3DxWare 10.9.14 (b745); the details
are in `PROTOCOL.md` inside each archive and in the repository.

> **Status:** everything here comes from decompiling the shipped Windows
> drivers.
>
> These **0.1.0 binaries were verified on a real SpacePilot Pro**: motion,
> buttons, both output paths, LCD image, ping, brightness, LED, and the
> daemon's key page with SHIFT paging (see `docs/HARDWARE_TESTS.md`).
>
> The SpaceMouse Enterprise and Giotto paths are untested on hardware. Please
> report what works and what doesn't.

### Downloads

| File | For |
|---|---|
| `tdxd-0.1.0-linux-x86_64.tar.gz` | 64-bit Intel/AMD PCs |
| `tdxd-0.1.0-linux-arm64.tar.gz` | 64-bit ARM (Raspberry Pi 4/5 with a 64-bit OS, etc.) |
| `tdxd-0.1.0-SHA256SUMS` | checksums for both archives |

The binaries are statically linked, so they need no libraries. Any reasonably
recent Linux kernel with `hidraw`, `uinput` and `usbfs` will do.

### Install

```bash
tar xzf tdxd-0.1.0-linux-x86_64.tar.gz && cd tdxd-0.1.0-linux-x86_64
sudo ./install.sh
sudo tdxd -v -v            # foreground, logs devices and button presses
```

Stop `spacenavd` first if it is running. `sudo ./install.sh --remove`
uninstalls everything except `/etc/tdxd.conf`.

### What it does

- **Motion and buttons:** 6-axis motion and all buttons, for 29 devices from
  the 3DxWare database plus 7 older ones (`tdxd -l` lists them). Output goes to:
  - a uinput device;
  - a spacenavd-compatible socket, for Blender, FreeCAD and other libspnav
    applications.
- **Settings:** sensitivity, per-axis invert/remap, deadzone, dominant axis, and
  button-to-key mapping, all in `/etc/tdxd.conf`.
- **SpacePilot Pro LCD (320×240):** shows key-label pages (SHIFT shows keys
  6–10) or any image. Also supports brightness and the ready check (ping).
- **SpaceMouse Enterprise LCD (640×150):** compressed frames and brightness.
- **Giotto LCD (1280×416):** buffered frames, rectangle updates, the slide and
  vertical-move animations, and the legacy `sp4LCD.bmp` path.
- **LEDs:** on/off for all devices, and RGB button/ring colours on Giotto.
- **`tdx-lcd`:** drives any of the three LCDs directly, for testing.

### Please test and report

1. **Device found:** `tdxd -l` and `ls /dev/hidraw*`.
2. **Input:** run `sudo tdxd -v -v`, then move the cap and press buttons. Check
   `evtest` for the "3Dconnexion … (tdxd)" device.
3. **LCD:** stop the daemon first, then try:
   - `sudo tdx-lcd fill bars`
   - `sudo tdx-lcd ping` (SpacePilot Pro)
   - `sudo tdx-lcd brightness 50`
4. **Image correctness:** if red and blue are swapped, the image is mirrored or
   upside down, or a slide goes the wrong way, please say so. These are the
   parts that are inferred rather than proven (see `PROTOCOL.md`, section 7).

Include `tdxd -V` and the `-v -v` log in any report.
