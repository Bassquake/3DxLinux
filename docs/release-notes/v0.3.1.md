## 3DxLinux 0.3.1 — Install with a double-click

This release adds `.deb` and `.rpm` packages, so 3DxLinux installs from the
desktop's software app with no commands. It also fixes the LCD applets, which
didn't start after installing 0.3.0.

### New

**Packages.** Double-click the `.deb` (Ubuntu, Debian, Mint, Pop!_OS) or the
`.rpm` (Fedora, openSUSE), click **Install** and enter your password. The
package:

- installs Python 3 and GTK 3 if they're missing;
- loads `uinput`, now and at every boot;
- sets up the udev rule, so you can use the device without root;
- enables and starts `tdxd`;
- enables the LCD Manager for every user and starts it in your session;
- replaces `spacenavd` if it is installed.

Removing the package from the software app undoes all of it. Your
`/etc/tdxd.conf` is kept across upgrades.

**Import 3DxWare look… button.** The 3DxWare artwork still can't ship with
3DxLinux, but importing it no longer needs a terminal either. In `tdx-settings`,
click **More ›**, then **About**, then **Import 3DxWare look…**, and pick your
3DxWare installer (`.exe`). The panel imports it for your user (no password)
and says how many images it took from which installer. It then restarts itself
and the LCD Manager, so the panel, the LCD Manager window, the device's
program list and the applets all switch to the Windows look. The About window
shows when the look was imported.

### Fixed

- **The LCD applets didn't start after installing 0.3.0.** Function Keys, RSS
  Feeds and Picture Viewer looked for their Python library in the wrong folder
  once installed ("No module named 'lcdapplet'"). They worked from the source
  tree, which is where they were tested. A new test now starts every program
  from the installed layout.
- **The LCD Manager and its applets:**
  - applets it starts now connect even when it runs on a non-default socket;
  - when it exits, it stops the applets it started;
  - after moving from `install.sh` to a package, its entries for the three
    applets follow them to `/usr/bin` instead of listing programs that can't
    start.

### Upgrading

- **From `install.sh` (0.3.0 or older):** remove that copy first, from the
  folder you installed it from, then double-click the package:

  ```bash
  sudo ./install.sh --remove
  ```

  Your `/etc/tdxd.conf` stays and the package uses it.
- **With the `.tar.gz`:** same as before, `sudo ./install.sh` from the
  unpacked folder.

For the Windows look, use **Import 3DxWare look…** in the settings panel's
About window once.

### Hardware status

Unchanged from 0.3.0 for the device. The x86_64 `.deb` was installed,
upgraded and removed on Ubuntu 22.04 (WSL) with a SpacePilot Pro attached: 3DxLinux
started and found the device, and the LCD Manager ran the three applets from
`/usr/bin`. The `.rpm` and the arm64 packages were built and inspected but not
installed, and a double-click install on a real Linux desktop is untested.
