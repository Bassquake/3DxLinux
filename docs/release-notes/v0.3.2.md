## tdxd 0.3.2 — LCD fix for desktop installs

This release fixes the SpacePilot Pro LCD on a normal Linux desktop. With the
0.3.1 packages, the LCD kept showing its idle "SpacePilot PRO" picture; motion,
buttons and the settings panel worked.

### Fixed

- **The LCD Manager couldn't use the LCD.** The udev rule that gives the
  logged-in user access to the device was numbered `99-`, which runs after
  systemd hands out that access (in `73-seat-late.rules`). Only root could open
  the LCD, and the LCD Manager runs as your user. The rule is now
  `70-3dconnexion-tdxd.rules`. Found on Kubuntu 26.04 LTS; it affects every
  install method, including the `.tar.gz` and `make install`.

### Upgrading

- **From the 0.3.1 package:** double-click the 0.3.2 one and click
  **Upgrade**/**Install**, then unplug and replug the SpacePilot (or log out
  and back in). The old rule is removed automatically.
- **If you used the workaround** (a copy in
  `/etc/udev/rules.d/70-3dconnexion-tdxd.rules`): it does no harm, but you can
  delete it after upgrading.
- **From `install.sh`:** run the new `sudo ./install.sh`; it replaces the old
  rule.

### Hardware status

The fix was confirmed on Kubuntu 26.04 LTS with a SpacePilot Pro: with the rule
in the new position, the LCD Manager took over the LCD and the applets ran. The
0.3.2 packages themselves were built and inspected; the `.rpm` and arm64
packages are still untested on hardware.
